## The goal (unchanged — this is the "same purpose" to resume with)

Build **one top-level kdevops-ng Windmill flow** that ties the whole pipeline
together:

> worktree setup → kernel build → qemu build → nix closure → **qsu guest
> bringup** → **run a testsuite** → **optionally destroy the guest**.

Requirements the user stated (verbatim intent):
1. User selects **which testsuite** (xfstests today; **blktests + more later**),
   **which guest**, **which kernel/version/etc.**, and **which sections/profiles**.
2. **Granular "Advanced" mode now**; a future **"Normal" mode** that hides knobs
   and bakes in heuristics/assumptions (easier to run).
3. **Testsuite is a swappable abstraction**, NOT hardcoded to fstests.
4. Inspired by the **kconfig SAT-solver / Luis's `ci-goal` feature-driven config
   vision** — a YAML requirement (filesystem/features/testsuite/tests) that
   *generates everything needed*. This is the **future layer**, not step one.
5. Long-run: users get **queried** "what testing do you want?" then the system
   generates all the stuff. Advanced = full customization; Normal = heuristics.

**NOTE the user said "the project has changed significantly"** right before asking
for this handoff — so re-confirm the goal/priorities at the start of the next
session; some of the above framing may have shifted.

### B. Windmill OpenFlow / subflow model
Docs read: `windmill.dev/docs/openflow`, `/docs/flows/flow_editor`. Key facts:
- Flow = DAG of `modules`; a module `value` is one of Identity / RawScript /
  PathScript / **ForloopFlow** / **BranchOne** (first match wins) / **BranchAll**
  (parallel). A module can be `type: flow path: f/x/y` — **subflow** — with
  `input_transforms` (static or `{type: javascript, expr}`).
- `skip_if` / `stop_after_if`, `suspend` (approval), retries, cache, concurrency,
  step mocking. Flow input `schema` = JSON Schema (drives auto UI; nested
  `type:object` groups; `showExpr` conditional display; dynselect via
  `format: dynselect-<fn>` / `dynmultiselect-<fn>`).

### C. Full kdevops-ng flow architecture map
An Explore agent produced a detailed map (file:line). Not duplicated here — the
essentials:
- **Subflow idiom already in use:** `f/qsu/bringup.flow` (GENERATED by
  `scripts/gen-bringup.py`, ~1461 lines) embeds `f/kernel/build`, `f/nix/build`,
  `f/qemu/build`, `f/qsu/boot` as `type: flow` subflows, gated by `skip_if` on
  `kernel_source`/`closure_source`/`qemu_source` (build|reuse|nixpkgs) + a
  `discover` step reading the reuse sidecar.
- **Build flows** (`same_worker: true`): `f/kernel/build` (config methods
  preset/make/fragments/skip; ~100-fragment enum; default preset
  `imageless_defconfig`), `f/qemu/build`, `f/nix/build` (render→lock→build_closure;
  closure inputs `profiles[]` + **`test_suites[]`** enum = blktests, fstests, gitr,
  ltp, mmtests, pynfs, selftests, sysbench).
- **qsu**: `f/qsu/{boot,stop,destroy,status}` + render steps
  (qemu-system/virtiofsd/nvme). Boot renders host `systemd --user` units, writes
  reuse sidecar `workers/shared/vm/<vm>.vars.json`.
- **fstests**: `f/fstests/check.flow` = discover→render_config→[reboot]→
  **sections (forloopflow)** [wipe→prepare→start→wait→collect]→report. Test
  selection = **groups|tests XOR** (under `check` group). Dynselect helpers
  `list_vms`, `list_sections`, `list_groups`. XFS section matrix in `common.py`
  (`xfs_catalog_text`, `xfs_profiles_matrix`).
- **CRITICAL GAP:** nothing composes bringup→test→teardown into one flow, and
  **"testsuite" is hardcoded to fstests** — `blktests` exists ONLY as a closure
  `test_suites` enum entry; there is **no `f/blktests/check` orchestrator**. This
  gap IS the work.
